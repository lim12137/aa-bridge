# DSH 自包含启动失败：第三方插件裸导入无法解析（2026-08-23）

## 现象

托盘「启动 dsh / 打开网页」反复失败，弹窗只报"dsh 启动后立即退出，或在 45 秒内没有响应"
（`%LOCALAPPDATA%\DshTray\dsh-tray.log` 连续 4 次同样的失败）。网页壳里偶见前端报错：

```
failed to import loader entry 5d0744c3 (@deepseek-ai/dsh-typert-registry):
client-modules: bundle script /plugins/@deepseek-ai/dsh-typert-registry/client.js?rev=... failed to load
```

第一反应容易误判为"DshTray 走了系统 PATH 的旧 Node/旧 dsh"——**误判**。
`dsh-web.log` 的崩溃栈全部指向 `M:\...\DshTray\res\dsh\dsh\...`，末尾打印 `Node.js v24.19.0`：
内置资源**确实被使用了**，是内置 dsh **启动即崩溃**；typert 报错只是进程死掉后
前端拉插件 bundle 失败的连带症状。

## 根因

第三方插件（如 `dsh-web-search-openai`，经 pnpm `link:` 以 junction 装进
`~/.dsh/profiles/web/node_modules/`）源码里的裸导入：

```js
import { WebError } from '@deepseek-ai/dsh-web';
```

Node 加载模块时会把 junction 解析回**真实路径**（`C:\Users\...\Documents\dsh-web-search-openai`），
裸导入从真实路径的祖先链解析 node_modules——Documents 链上什么都没有 →
`ERR_MODULE_NOT_FOUND`。而新版 dsh 的 cordis loader 把插件导入失败当**致命错误**，
整个 `dsh web` 进程退出 → 45 秒超时。

profile 的 hoisted 树（`profiles/web/node_modules/@deepseek-ai/`）是**空目录**，
`--preserve-symlinks` 也救不了；loader 的 `internal.import` 只作用于 entry 名，
管不到插件文件内部的 import。

## 修复（机器级）

给插件目录补 node_modules，三个 junction 指向 DshTray 内置 dsh 的同名包
（与启动器实际使用的运行时版本一致）：

```bat
mklink /J <插件目录>\node_modules\@deepseek-ai\dsh-web      M:\1Tools\DshTray\res\dsh\dsh\node_modules\@deepseek-ai\dsh-web
mklink /J <插件目录>\node_modules\@deepseek-ai\dsh-settings M:\1Tools\DshTray\res\dsh\dsh\node_modules\@deepseek-ai\dsh-settings
mklink /J <插件目录>\node_modules\@deepseek-ai\schemastery  M:\1Tools\DshTray\res\dsh\dsh\node_modules\@deepseek-ai\schemastery
```

注意：junction 目标写死了 DshTray 安装路径，**移动/重装 DshTray 文件夹后需重建**。

## 验证

```
内置 node 起 dsh web --no-open --port 7398（第二实例法）
→ 端口 LISTENING，首页 200，/plugins/dsh-web-search-openai/client.js 200
→ 日志：[dsh-web-search-openai] v0.6.2 registered
```

## 本次同步修复的 DshTray 源码问题（v1.4）

1. **启动失败只报笼统超时**：现在从 `dsh-web.log` 提取关键崩溃行
   （`Cannot find package` / `failed to import loader entry` / `duplicate loader entry id`）
   直接弹窗展示，一次定位根因。
2. **自包含模式「升级 dsh」装错位置**：原实现 `npm install -g` 会把新版装进
   `res\nodejs\node_modules`（启动器根本不用它），升级"成功"却永远跑旧版。
   现改为 `npm install --prefix res\dsh`（标准布局 `res\dsh\node_modules\@deepseek-ai\dsh`），
   启动器同时识别发布布局与 npm 标准布局（标准布局优先），升级成功后自动清理旧布局目录。
