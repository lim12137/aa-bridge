> 来源：`dsh-web-search-openai` 从 v0.4 到 v0.5.2 的三轮真实故障。
> 姊妹篇：《DshTray/docs/2026-08-22-dsh启动故障修复记录.md》（本篇是其通用化+后续）。

## 一、六条铁律（每条都付出过一次完整启动失败的代价）

### 1. bundle patch 的 insert 铁律 —— `duplicate loader entry id`

- **机制**：`dsh.profile.bundles` 列表里的每个包，其自带 `cordis.patch.yml` 会作为一层参与组合；根 `cordis.yml` 是空的，最终 entry 列表 = 各 bundle 层依次叠加 → profile 层 `cordis.patch.yml` → 家目录层 → `--patch` 覆盖层。
- **铁律**：只能 `- insert:` **没有任何更早层创建过的 id**。官方包的行（如 dsh-base 插入的 `web`）再 insert 一遍 = 整个 profile 启动崩溃 `duplicate loader entry id: web`。loader 在 `update()` 里对最终列表逐 id 查重（cordis-plugin-loader/lib/index.js）。
- **配套规则**：裸行 `- id: x / config:` 是**整行 config 替换**语义，必须重申目标行的全部键（好在 `web` 行只有 `searchProvider` 一个键）。`disabled: true` 是行级属性，可以单独覆盖不动 config。
- **验证方法**：
  - 静态：`dsh --profile <name> --dump-config` 打印合成树（带 `# == 文件名` 分层注释），数关键 id 出现次数；
  - 动态：用 `node <dsh-bin> web --no-open --port 7398` 起第二实例看日志，18 秒后强杀，不碰生产端口。

### 2. `.env` 变量禁用 `DSH_` 前缀

- **机制**：dsh-app-boot 的 `BOOTSTRAP_PREFIXES = ["DSH_", "XDG_", "DYLD_", "BASH_FUNC_"]`。启动目录或 `$DSH_HOME` 下任何 `.env` 里出现这些前缀的变量 → **直接拒绝启动**："only the launching environment may set"。
- **铁律**：插件自定义环境变量**永远不要用保留前缀**。本项目从 `DSH_SEARCH_*` 改名 `WEB_SEARCH_*`，旧名仅作为「已导出的真实环境变量」兼容读取（新名优先）。
- **注意区分**：插件自己用 `ctx.fs.readText('.env')` 读工作区 `.env` 不经过这个守卫（运行时文件读取），守卫只管 boot 时的 env 层装载——但同一个文件两种读者并存时，必须按最严格的一方命名。

### 3. `link:` 依赖在 profiles/*/node_modules 下可能是物理拷贝

- 改了源码、重启了、没生效？第一怀疑点：`profiles/<name>/node_modules/<pkg>` 是不是早上复制的旧拷贝。
- 解法定型：profile 目录里跑 `pnpm install`（nodeLinker: hoisted），让 `link:` 变成 junction 指向 ASCII 安装源；之后源码改动即生效。
- Windows 中文路径经 pwsh→dsh→pnpm 进程链会编码损坏导致 junction 断裂——安装源一律放纯 ASCII 路径（`~/.dsh/local-plugins/`）。

### 4. 双 Node 共存陷阱

- 新版 dsh 需要 `node:zlib` 的 `createZstdDecompress`（Node ≥22.15 / 24.x）；PATH 里残留的 v22 会报 `does not provide an export named 'createZstdDecompress'`。
- 已固化：`D:\nodejs` 本体已换成 v24.19.0。任何「模块导出不存在」类报错先查 `node -v`。

### 5. 设置卡片可见 = 双重条件交集

Plugins 标签页渲染卡片当且仅当：

```
host settings.describe() 返回的命名空间集合  ∩  客户端注册进 settings.plugin.item 的 key 集合
```

- Host 半：`installSettingsSection(ctx, namespace, schema, seed, {...})` 成功执行（启动日志 `[pkg] vX registered` 只证明宿主半挂载，不证明卡片可见）。
- Client 半：`window.__ModuleLoader__.load({id: <包名>, factory})` 格式的 lazy-CJS，apply 里 `ctx.slots.inject("settings.plugin.item", function*(){ yield ctx.slots.register({key: <namespace>}, Card) })`。
- 服务端交付链自查顺序：启动日志 → 页面 HTML 是否含包名 → `GET /plugins/<包名>/client.js` 是否 200 且内容最新 → Slot 探针看占用。

### 6. 页面模块图只在整页加载时构建 —— 「重启后没有卡片」的最后一块拼图

- DSH 网页的 `__DSH_BOOT__` 模块表烘焙在 HTML 里；服务重启后 SSE 会自动重连，RPC 一切正常，但**老标签页的模块图还是旧的**，新插件的客户端半永远不会被加载。
- **症状指纹**：Slot 探针显示 `settings.plugin.item` 连官方三张卡（shell / agent-loop / web-search-deepseek）都没占位 → 这不是你的插件坏了，是页面本身是旧的。
- **处置**：重启 dsh 后必须**硬刷新浏览器（Ctrl+F5）**。给用户的验证清单里永远要有这一条。

## 二、测试方法论沉淀

1. **独立真代码测试台**：peer 依赖（@deepseek-ai/dsh-web 等）用 stub 目录顶替、schema 库 junction 到真身、源文件 copy 后 import——测的是发布代码本体而非复制逻辑。入口：`lib/index.js` 导出 `__internals`（纯函数集合，不影响 cordis 加载）。
2. **探针先行，数据说话**：「思考强度要不要传」不争论，直接对中转实测三种档位的耗时与引用数（minimal 快 32%、引用不变），用测量结果定默认值。
3. **降级链的价值要用故障验证**：gpt-5.4-mini 全程零引用、上游间歇 502——都被 parallel 兜底和链内 fallthrough 吸收，「200 但无引用视为未搜索」的设计被真实故障反复证明正确。
4. **组合验证三层**：`--dump-config` 静态数行 → 中性 cwd 短启动 → 生产 cwd 短启动（专测 env 守卫类问题）。
5. **远端诊断顺序**：进程 PID/启动时间 → 托盘日志关键行 → 页面 HTML 启动图 → client.js 字节比对 → Cordis inspect 的 Slot 占用（注意第 6 条的判读陷阱）。

## 三、排障速查表

| 症状 | 先查 |
| --- | --- |
| 启动即崩 duplicate loader entry | 各 bundle patch 有没有 insert 既有 id |
| 启动即崩 only the launching environment | cwd / ~/.dsh 的 .env 里有没有 DSH_*/XDG_* 变量 |
| does not provide an export named 'createZstdDecompress' | node -v（需 ≥22.15/24） |
| 改了源码行为不变 | profiles/*/node_modules 是拷贝还是 junction |
| 重启后设置里没卡片 | 浏览器是否硬刷新过；client.js 是否 200；Slot 占用是否连官方卡都缺 |
| 搜索 200 但无引用降级 | 该中转是否真·OpenAI 透传（剥 tools 字段的中转永远零引用） |

## 四、当前固化的正确形态（v0.5.2）

- patch：唯一 insert 自身 id + 裸行覆盖 `web.searchProvider` + 停用 deepseek 行
- 配置词汇：`WEB_SEARCH_CHAIN/MODE/MODEL/AUTO_ORDER/XSEARCH/REASONING/FALLBACK_KEY/FALLBACK_BASE_URL/MAX_OUTPUT_TOKENS/TIMEOUT_MS`
- 默认链：parallel（免 Key MCP）→ openai（luna → terra → 5.4，思考强度 low）
- 双 profile 经 junction 指向 `~/.dsh/local-plugins/dsh-web-search-openai`
