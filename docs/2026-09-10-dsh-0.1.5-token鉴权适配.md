# DSH 0.1.5.x 适配：网页 token 鉴权 + 升级命令验证（2026-09-10）

## 背景

dsh（@deepseek-ai/dsh）已发布 **0.1.5-rc.1**（latest，2026-09-10），本机从
0.1.5-alpha.1 升级后，DshTray「打开网页」打开的是裸地址
`http://127.0.0.1:7331/`，**新版返回 401 Unauthorized**。

## 根因

dsh 0.1.5.x 的 web 服务强制 token 鉴权：每次启动在 stdout（即 `dsh-web.log`）
打印一次性地址 `dsh web: http://127.0.0.1:7331/?token=<43位随机串>`，
裸地址一律 401。DshTray 此前写死打开 `WEB_URI`（无 token）。

## 修复（v1.5）

新增 `readWebUrlFromLog()`：从 `dsh-web.log` 尾部 8000 字节提取**最近一次**
带 token 的地址，「打开网页 / 浏览器壳刷新」全部改用该地址；日志无记录时回退裸地址。

### aardio 模式匹配的三个坑（实测 + 官方文档佐证）

见 `docs/library-guide/builtin/string/patterns.md`：

1. **冒号 `:` 是模式特殊符号**——匹配「任意 UTF-8 多字节字符」，不是字面冒号。
   URL 里的 `http:` 会让模式必失配，字面冒号要写 `\:`。
2. **模式串要写在双引号（原样字符串）里**；单引号是转义字符串，反斜杠须写双份。
   单/双引号混用时表现自相矛盾，极易误判。
3. 最稳写法：**模式里完全不出现魔法字符**。本实现用
   `WEB_PORT ++ '/[?]token=[A-Za-z0-9_-]+'`（端口数字 + 方括号类），零反斜杠、零冒号。

## 升级命令实测（2026-09-10）

```
npm install -g @deepseek-ai/dsh@latest --no-fund --no-audit
→ 0.1.5-alpha.1 → 0.1.5-rc.1（added 3, removed 23, changed 516）
→ dsh web --no-open --host 127.0.0.1 --port 7399 启动成功
→ 第三方插件 [dsh-web-search-openai] v0.6.2 正常 registered
```

结论：**fallback 模式（系统 dsh）的升级命令正确，0.1.5-rc.1 + 现有插件兼容**。
注意：0.1.5-rc.1 的依赖树已不含 `@deepseek-ai/dsh-web`（拆分为独立包
`@deepseek-ai/dsh-web@0.0.1-rc.1`）；第三方插件若裸导入该包且 profile 未提供，
会复现 `ERR_MODULE_NOT_FOUND`（见 2026-08-23 文档），本机 profile 已由 dsh 自动补齐。
