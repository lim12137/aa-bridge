# DSH 启动故障修复记录（2026-08-22）

## 现象

通过托盘（DshTray）菜单「启动 dsh」后，dsh 网页服务反复启动失败，日志
（`%LOCALAPPDATA%\DshTray\dsh-web.log`）中出现：

```
Error: dsh: plugin tree failed to load: duplicate loader entry id: web
```

中间阶段还出现过另一类错误（手动用默认 PATH 测试时）：

```
The requested module 'node:zlib' does not provide an export named 'createZstdDecompress'
```

## 根因

两件独立的事情叠加：

1. **插件 patch 与新版 dsh 语义冲突**。升级后的 dsh（`@deepseek-ai/dsh`，cordis-plugin-loader）
   会为 profile bundles 列表中的插件**自动注册 loader entry**；而本地插件
   `~\.dsh\local-plugins\dsh-web-search-openai\cordis.patch.yml` 仍用旧写法
   `- insert: {id: web, name: '@deepseek-ai/dsh-web'}` 额外插入一个 `id: web` 条目，
   与 `dsh-web-app` bundle 自带的 `web` 条目冲突 → `duplicate loader entry id: web`。
2. **机器上存在两份 Node**：`D:\nodejs`（v22.11.0，PATH 默认命中）与
   `D:\nodejs-v24.19.0`（v24.19.0）。新版 dsh 需要 `node:zlib` 的
   `createZstdDecompress`（v22.15+ 才有），用 v22 启动即崩。

## 最终方案（按用户要求：只用加强版搜索插件，删除 Node 22）

### 1. 弃用 `dsh-web-search-openai`，只保留 `dsh-web-search-enhanced`

`~\.dsh\profiles\web\package.json`：

```json
{
  "name": "dsh-profile-web",
  "private": true,
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "dsh-web-search-enhanced"
      ]
    }
  },
  "dependencies": {
    "dsh-web-search-enhanced": "link:C:/Users/.../.dsh/local-plugins/dsh-web-search-enhanced"
  }
}
```

### 2. 修正加强版插件的 cordis.patch.yml（两处，内容相同）

- `~\.dsh\local-plugins\dsh-web-search-enhanced\cordis.patch.yml`
- `~\.dsh\profiles\web\node_modules\dsh-web-search-enhanced\cordis.patch.yml`
  （注意：这是**物理拷贝**不是符号链接，改了源目录不会自动同步！）

最终内容——删除了 `insert` 自身的段（bundles 已自动注册，再 insert 就重复）：

```yaml
# Bundle patch for dsh-web-search-enhanced.
# Three-tier search: GPT Responses → Parallel (free) → DuckDuckGo (fallback)

- id: web
  config:
    searchProvider: enhanced-search

- id: web-search-deepseek
  disabled: true
```

### 3. 用 Node v24.19.0 替换 D:\nodejs 里的 v22

保留 `D:\nodejs\node_global\`（dsh 全局安装位置）和 `node_cache\`，
其余 Node 本体文件（node.exe / npm / node_modules 等）替换为
`D:\nodejs-v24.19.0` 的内容。现在 PATH 里的 `node` 无论解析到哪个目录都是 v24.19.0。

## 新版 dsh 插件 patch 写法规律（避免再踩坑）

- bundles 列表里的插件会**自动注册** entry，插件自己的 patch **不要** `insert` 自身 id。
- 对内置条目（如 `web`）改配置用**按 id 覆盖**写法，不要带 `name`：
  ```yaml
  - id: web
    config:
      searchProvider: xxx
  ```
- `link:` 依赖在 `profiles/*/node_modules/` 下可能是物理拷贝，修改源插件后要**两处同步**。

## 验证

```
$ node -v          → v24.19.0
$ dsh web --no-open --host 127.0.0.1 --port 7331
dsh web: http://127.0.0.1:7331     （端口监听，HTTP 200）
```

托盘程序（DshTray v1.1）本身无需改动。
